# Request Desk

A local desk for the service-request spreadsheet. It checks each request, categorises it with rules you can edit, writes a suggested acknowledgement, and marks the rows a person should see.

The ten sample requests are loaded the first time the database is empty. Sign in at [http://127.0.0.1:8000](http://127.0.0.1:8000).

- Username: `admin`
- Password: `RequestDesk!2026`

## What you can do

- **Desk** shows how many requests are stored, how many need a person, and which rule is in force.
- **Requests** is the table. Filter it, open a row, add one request, upload a CSV, or download the table.
- **Download all** exports every row, including the category, acknowledgement, and review reasons. That file can be uploaded again. A request ID that already exists is updated and analysed again. A new ID is added.
- **Rules** is the admin panel. Add a category, change keywords, edit an acknowledgement, or turn a review switch on or off. Then use **Re-run analysis** on the Requests page so the rows already in the table pick up the change.

## Start it again

From this folder:

```powershell
.\.venv\Scripts\python.exe run.py
```

`run.py` reads the database settings from `.env`, starts that database if it is stopped, and opens the site at [http://127.0.0.1:8000](http://127.0.0.1:8000). It does not use the PostgreSQL servers already listening on ports 5432 and 5433.

Copy `.env.example` to `.env` on a new machine and set `PG_BIN` to the folder that contains `pg_ctl`.

If Docker Desktop is running, you can use that instead. Stop the project database first so the ports do not clash:

```powershell
& "C:\Program Files\PostgreSQL\15\bin\pg_ctl.exe" -D .pgdata stop
docker compose up --build
```

Then open [http://localhost:8000](http://localhost:8000). The same login applies. The password is set the first time the database is created.

## Tests

From this folder:

```powershell
.\.venv\Scripts\python -m pytest backend\tests -q
```

The three task checks, plus a few guards around them, are in `backend/tests/test_triage.py`:

1. `data/sample_requests.csv` — the ten complete requests are categorised, and the rows that need a person are flagged.
2. `data/test_missing.csv` — a blank summary and a priority that is not allowed.
3. `data/test_attention.csv` — a category that disagrees with the summary, a high-priority request, and a completed request.

The result files are `data/sample_results.csv`, `data/test_missing_results.csv`, and `data/test_attention_results.csv`.

## Security and limits

- One admin account. The password is stored as a hash. The session cookie is HTTP-only.
- Request text is not sent to an external service. Acknowledgements are filled from templates, not generated by a model.
- Spreadsheet cells that start with `=`, `+`, `-`, or `@` are prefixed on export so a spreadsheet does not treat them as formulas.
- The project database accepts local connections without a password, so it can start without sharing the credentials of the other PostgreSQL installs. The website still requires the admin login. Do not expose this database or the site beyond this machine.
- Built for a team spreadsheet, up to 5,000 rows and 2 MB. The schema is created on startup rather than with versioned migrations.
